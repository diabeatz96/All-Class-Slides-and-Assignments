The Safety Inspector

No ride opens until the inspector signs off.

Getting started

  1. Open safety-inspector/guestbook.js in VS Code. Bronze and Silver are in there; Gold happens right on this page.
  2. Edit and save. This page updates by itself.
  3. Something broke? Open the Console (Cmd+Option+J or Ctrl+Shift+J). Red text names the line.

Booth Tickets

  • Bronze Run the Broken Sign experiment below, then explain to the inspector in one sentence why the guestbook renders with textContent.
  • Silver Write validate() in guestbook.js: trim, name required, message 1 to 280 characters, show a friendly error.
  • Gold Complete all five Inspection Cards below with the safe fix written out. Your answers save in this browser.
  • Bonus Write the Supabase RLS policies at the bottom of guestbook.js so a signed-in user can only edit their own entries.

Ride 1: The Midway Guestbook

Visitors leave a message on the guestbook. Your job is to keep the guestbook safe no matter what anyone types.

Bronze: the Broken Sign experiment

  1. Sign the guestbook with the message <b>Hello</b>. You see the tags as plain text. Safe!
  2. Tick Broken Sign mode below. The same entry is now bold: the browser treated a visitor's typing as HTML.
  3. Still in broken mode, sign with <img src="nope" onerror="alert('The sign talked!')">. A popup means a visitor's text just ran as code on your page. That is XSS. It pops again whenever the list redraws, because it is saved in the list: stored XSS.
  4. Untick broken mode. Now explain to the inspector: what does textContent do differently from innerHTML?

Gold: Inspection Cards

Each team inspects these five rides and writes the safe fix in the box. Open a hint only if you are stuck.

1. The Leaky Ticket Booth

A secret service key is pasted straight into a React component. Where should secrets live, and which keys are actually safe to ship to the browser?

HintAnything in front-end code can be read with View Source. Supabase gives you two keys; only one is labeled safe for a browser.

2. The Unlocked Prize Closet

A Supabase table has Row Level Security turned off. Who can read and change every row right now? What policy would limit users to their own rows?

HintThe anon key is public, so "anyone with the key" means anyone. Policies compare the row's owner column to auth.uid().

3. The Talking Sign

User messages are dropped into the page with innerHTML. Why does the browser treat that text as markup, and what should we use instead?

HintYou just did this one in the Broken Sign experiment. What does React do with {message}?

4. The Bottomless Bucket

The form accepts empty names and 50,000 character messages. Where do we validate, and why is client-side validation not enough by itself?

HintTwo places. Could someone send data to your database without ever loading your form?

5. The Open Diary

The .env file got committed to GitHub. What goes in .gitignore, and what must you do with a key that was already pushed?

HintDeleting the file in a new commit does not erase old commits, and bots scan GitHub for keys within minutes.
